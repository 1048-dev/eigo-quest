### 決めたこと（理由）
- **デモユーザーの DB の記録は使わず、「この端末で遊んだ分」を端末に記録して送る方式にしました。** デモユーザーはおためしの全員で共有している1人のユーザーなので、DB からコピーすると ほかの人が遊んだ分（ほかの家のデータ）まで入ってしまうためです。デモユーザーの記録は読みも消しもしない（＝コピー）ので、ほかのおためしの人にも影響しません。
- **送られてくる記録は「ブラウザが言っていること」なので、サーバーで確かめます。** 存在しないレッスン・テスト・項目、未来の日付、アリーナ/お宝（マップに無いテスト）は捨てます。コインは「そのレッスン数・テスト・遊んだ日数で おためしで もらえる最大値」で おさえます（ブラウザの値を書きかえても大量のコインは入りません）。レッスン数そのものは1日の上限が無い仕様なので制限していません。
- **1回だけの仕組み**: 端末ごとのランダムな おためしID を作り、CoinLedger の `idempotencyKey = trial-carry:<ID>`（DB 全体でユニーク）を「引き継いだ しるし」にしました。同時に2回送られても、別の子・別の家にもう一度送られても、2回目は何もしません。これにより新しいテーブルを増やさずにすみました。端末側にも「聞いた」しるし（はい/いいえ）を残します。
- **引き継ぎの確認は暗証番号なし**にしました（「だれが あそぶ？」で子どもが選んだ直後に出るため）。自分の家の子どもにしか入らず、害が無いためです。画面に「おうちの方と いっしょに きめてね」と書いています。
- 引き継いだテストの合格は「一発合格ではない・コイン0」の記録として入れます（コインは引き継ぎのコインにまとめて1行で台帳に入るので、二重に数えません）。
- 子どもが顔を変える API も暗証番号なしです（子どもが操作する前提。名前・学年などの変更は今までどおり暗証番号が必要）。
- 開発用に `.tmp/` を .gitignore に追加しました（マイグレーション作成時の古い schema のコピー置き場）。
